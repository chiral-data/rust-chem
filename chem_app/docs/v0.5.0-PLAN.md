# v0.5.0 — Floating-window workbench UI

Milestone plan. Tracking issue: [#112](https://github.com/chiral-data/rust-chem/issues/112).

Branched from `main` at `ddd3a89` (`2D structure depiction (v0.4.0) (#101)`).

## Why the panel shell is being replaced

v0.3.0 broadened `chem_app` from a fingerprint demo into a workbench. v0.4.0 gave it
structure depiction. Both added to the shell v0.2.0 shipped — a `TopBottomPanel`, a left
`SidePanel`, a right `SidePanel` and a `CentralPanel`, all drawn unconditionally at the
end of `update()`:

```rust
self.top_panel(ctx);
self.dataset_panel(ctx);
self.query_panel(ctx);
self.results_panel(ctx);
self.molecule_detail_window(ctx);
```

Nothing can be closed, nothing reopened, and there is nowhere to put a new view except
inside a panel that already exists. So the three things the app does are scattered across
regions that have nothing to do with them:

| Concern | Where its pieces live today |
| --- | --- |
| **Data** | files list, dataset table (left panel, capped at 300px while holding the app's widest content) |
| **Operations** | fingerprint settings + aromaticity (left), query + search (right), GPU/CPU (top bar), 2D coordinates (nowhere — implicit, via `ensure_coords` on row click) |
| **Visualization** | display options (left), query structure + fingerprint bits (right), results (central), structure/atoms/bonds (a floating window) |

Three consequences worth naming, because they are what the milestone is measured against:

- `structure_display_section` governs every structure drawn anywhere in the app, from
  inside the **data** panel.
- The dataset table has up to seven columns in a 300px column, so SMILES and formula are
  unreadable at any real width — and thumbnails are 64×48 partly because there is nowhere
  wider to put them.
- `molecule_detail_window` pins one egui id (`Id::new("molecule_detail_window")`) and the
  app keeps one selection, so only one molecule is ever open. Comparing two hits of a
  similarity search — what a similarity search exists to set up — is not possible.

## Target layout

A menu bar over a free canvas, with three floating windows:

```
┌─ 🧪 Chem Workbench │ File  View ──── GPU|CPU  FPS ─┐
│                                                    │
│   ┌ Data Sources ────┐   ┌ Data Visualization ─┐   │
│   │ files / table    │   │ display options     │   │
│   └──────────────────┘   │                     │   │
│                          │ query structure     │   │
│   ┌ Operations ──────┐   │ fingerprint bits    │   │
│   │ fp · arom · 2D   │   │                     │   │
│   │ search           │   │ results ranking     │   │
│   └──────────────────┘   └─────────────────────┘   │
└──────────────── (empty canvas) ────────────────────┘
```

Two columns, half and half: Data Sources above Operations on the left, Data
Visualization taking the right on its own. Matched to what the windows ended up
holding — the left pair are lists and controls that don't need height, while
Data Visualization carries a structure, a fingerprint grid and the results list
all at once. The `Compute` menu in the original sketch was built and then
dropped; see #103.

- **Menu bar** — File (load file, load examples), View (toggle windows, reset layout),
  Compute (GPU/CPU), with the GPU/CPU chips and FPS readout staying right-aligned.
- **Free canvas** — `CentralPanel` draws an empty workspace. No content lives there.
- **Window registry** — windows have a stable id, a title and an open flag; `update()`
  iterates the registry instead of naming windows one at a time.

## Scope decisions

- **Pure floating, not hybrid.** `CentralPanel` becomes empty rather than keeping search
  results docked. A hybrid shell would leave visualization split between a docked panel
  and a floating window — the exact scattering this milestone exists to undo. Cost: every
  panel must be ported, and first launch needs a sensible default layout so a new user
  never meets a blank canvas.
- **No docking layer.** egui has no built-in docking, so drag-to-dock means writing or
  vendoring one. That is a milestone of its own, and speculative before floating windows
  have been lived with.
- **State separation first (#102).** Building windows against the 30-field god struct and
  splitting it afterwards means writing them twice.
- **Still no `Operation` trait.** #99 evaluated one across all four operations and found
  their signatures share nothing — a trait added a layer without removing one, and
  `Task<T>` holds the async plumbing instead. #105 groups operations in the *UI*, which is
  a different claim from unifying their types. The same test applies to #102: if the split
  leaves `app.rs` longer and harder to follow, saying so is a valid outcome.
- **Layout persists, data does not (#108).** Geometry and view settings are restored;
  datasets, fingerprints and results are not. Restoring a fingerprint cache raises
  correctness questions — a cache stored under one radius, restored under another — that
  layout does not.
- **Visualization backlog included.** #109/#110/#111 were left unfiled in #86 pending a
  decision on scheduling. They belong with the visualization window; #111 in particular
  needs #106 to settle where results live.

## Out of scope

- **Reaction rendering** ([#85](https://github.com/chiral-data/rust-chem/issues/85)) —
  stays unscheduled. It is chemistry work, not UI work, and wants its own home in the
  visualization window once #106 exists.
- **Docking / tabbed windows** — see scope decisions.
- **Dataset persistence (IndexedDB)** — still deferred; #108 covers layout only.
- **Removing a loaded file** — raised in #104 but not committed to there. It touches the
  active-dataset reset path and deserves its own issue rather than being smuggled into a
  layout story.
- **PNG export** — #109 covers SVG; rasterising is a different mechanism.
- **Stereochemistry, condensed pseudo-element groups** — unchanged from #86.
- [**#69**](https://github.com/chiral-data/rust-chem/issues/69) — SMILES parser
  mis-tokenizes back-to-back bare ring-closure digits. Pre-existing, still open, still
  unscheduled.

## Behaviour that must survive the move

Details that are load-bearing today and easy to lose in a port:

- **Query debounce.** The SMILES box waits `QUERY_DEBOUNCE` (300ms) and drives
  `request_repaint_after`, so a blocking GPU dispatch does not fire per keystroke (#105).
- **Thumbnail option override.** The dataset table's `StructureOptions` override — padding
  2.0, forced `ShowCarbons::Default`, fit-to-rect — is deliberate: a 64×48 cell is read as
  a shape, and `ShowCarbons::None` would draw methane as an empty cell. Keep it an
  override; do not fold it into the shared options (#106).
- **`prepare_thumbnails`** keeps per-row layout off the draw path. Any new
  structure-per-row surface goes through it, #111 included.
- **GPU/CPU chips carry behaviour**, not just status: clicking retries init (`retry_gpu`)
  or forces CPU. Whatever the menu bar keeps has to keep that (#103, #105).
- **Detail-window layout cache.** `detail_molecule` exists because `ensure_coords` on a
  large molecule is not free. #107 makes it per-instance rather than dropping it.
- **Active-dataset reset.** Row indices are invalidated when the active dataset is
  swapped, alongside `dataset_fingerprints` and `search_results`. #107's windows are keyed
  by row, so they must be closed or rebound on that path.
- **Viewport clamp.** `ctx.content_rect().height() - 80.0` keeps a window from growing
  off-screen; it stays, applied per window.
- **wasm32 parity.** Every path here exists on both targets — `Task<T>`, the pending
  slots, `AsyncFileDialog`. #108's persistence needs native storage *and* web
  `localStorage`.

## Definition of done

- The three named windows exist, are toggleable from the View menu, and each owns both its
  content and the settings that govern it.
- No content is drawn in `CentralPanel`.
- Several molecule detail windows can be open at once.
- Layout and view settings survive a restart on native and a reload on web, and a bad
  layout is recoverable from the View menu.
- Native and web builds both pass CI; no `#[cfg(target_arch)]` regressions over the
  13 remaining after #99.
- `CHANGELOG.md` records the milestone, with known limitations named as v0.4.0 did.
